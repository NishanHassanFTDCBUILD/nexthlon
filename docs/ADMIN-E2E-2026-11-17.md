## Issues found and fixed during this pass

1. **Duplicate initial timeline milestone.** The admin order template always inserted “Order placed” and then rendered the same event from history. It now inserts a fallback only when history has no placed event. Browser verification found one placed entry afterward.
2. **Contradictory referral settings copy.** The section claimed rewards were credited at signup, while the actual rule and hint paid after the first delivered order. The section now states the delivery rule; verified in the browser.
3. **Ambiguous dashboard revenue labels.** The paid revenue KPI excluded unpaid orders, but product/category rankings included their ordered item values. Labels now say “Order value”, explicitly including unpaid orders and values before order discounts/refunds. The calculations and data were preserved. Browser verification confirmed the revised chart heading and tab.

No animation files, 3D scenes, motion timing or financial calculations were changed in this pass.

## Automated checks

The suite reported **252 entries: 221 passed, 2 failed, 29 skipped**. The two failures were the localhost HTTP CSP and multipart-upload probes, blocked by `EACCES`. Optional database suites were skipped without a configured test database. These blocked/skipped checks are not counted as passed.

The three edited admin templates compiled. Their visible changes were also verified in the authenticated browser. The 16 existing failure-injection tests for commerce recovery had passed in the preceding fix verification; real-MongoDB and gateway behavior remain separate release checks.

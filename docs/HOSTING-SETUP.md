# Before you host: the database and the photos

Two things must live outside your computer (and outside the server) before Nexthlon can go live:

1. **The database**: MongoDB Atlas.
2. **The product photos**: Cloudinary (no card needed); the site uploads to it and visitors download through its CDN.

You do the clicking in each service's website (they need your account, card and passwords, which only you
should enter). The code side is done: you put the values into settings, then run two check commands.

Menu names in these services change now and then; the steps give the idea and the exact words to look for.

---

## Part 1: MongoDB Atlas (the database)

### 1. Create the cluster

1. Sign up at <https://www.mongodb.com/atlas> and create an **organization** and a **project** (call it `Nexthlon`).
2. **Create a cluster** (Build a Database):
   - **M0 (Free)** is fine for a soft launch (512 MB, shared). Move to **M10** when real orders arrive: it adds
     automatic backups and more power. Upgrading later is one click and keeps your data.
   - **Provider and region**: AWS, **Mumbai (ap-south-1)**: closest to Indian customers. Put your web server in
     the same region when you can.
   - Name it `nexthlon`.

### 2. Make a database user for the app

**Database Access → Add New Database User**

- Authentication: **Password**. User name: `nexthlon-app`. Use **Autogenerate Secure Password** and copy it somewhere safe.
- Privileges: **Specific privileges → readWrite on database `nexthlon`** (or "Read and write to any database").
  Do not use an "Atlas admin" user for the app.

### 3. Allow the connection

**Network Access → Add IP Address**

- For your own computer: **Add Current IP Address**.
- For the host: most platforms (Render, Railway...) connect from changing addresses, so the practical choice is
  **Allow access from anywhere (0.0.0.0/0)**. This is acceptable **only** because the user has a long random
  password and Atlas requires an encrypted (TLS) connection. When you move to a paid cluster with a fixed host
  address, replace it with that address (or use a private endpoint).

### 4. Get the connection string

**Database → Connect → Drivers → Node.js** shows something like:

```
mongodb+srv://nexthlon-app:<db_password>@nexthlon.ab1cd.mongodb.net/?retryWrites=true&w=majority&appName=nexthlon
```

Change it in **three** ways before you use it:

1. Replace `<db_password>` with the real password, **including the `<` `>`**.
2. If the password has special characters, URL-encode them (`@` → `%40`, `:` → `%3A`, `/` → `%2F`, `#` → `%23`, `?` → `%3F`).
   Autogenerated passwords usually have none.
3. **Add the database name** after the host, before the `?`:
   `...mongodb.net/nexthlon?retryWrites=true...`. Without it MongoDB uses a database called `test`, and the app
   will warn you about it.

Final result:

```
mongodb+srv://nexthlon-app:YourPassword@nexthlon.ab1cd.mongodb.net/nexthlon?retryWrites=true&w=majority&appName=nexthlon
```

### 5. Put it in `.env` and test it

Open your local `.env` (never commit it, never paste it in chat or email) and set:

```
MONGODB_URI=<the string above>
```

Then:

```bash
npm run db:check
```

It connects, shows the cluster, database and what it found, tests that the user can read **and** write, and if
anything is wrong it says what to fix (wrong password, IP not allowed, no database name...). It never prints the
address or the password.

### 6. Fill the new database

A new database is empty. Start the app once (`npm start`: it creates the indexes), then:

```bash
npm run seed:admin      # the first administrator: set ADMIN_NAME, ADMIN_EMAIL, ADMIN_PASSWORD first
npm run seed:products   # optional: the sample products. For the real store, add products in the admin console.
```

If you want to move your **existing local data** instead (products, categories, orders you made while
developing), use MongoDB's own tools, which copy everything exactly:

```bash
mongodump --uri="mongodb://127.0.0.1:27017/nexthlon_week7" --out=dump
mongorestore --uri="<your Atlas string>" --nsFrom="nexthlon_week7.*" --nsTo="nexthlon.*" dump
```

(Install them from <https://www.mongodb.com/try/download/database-tools>.) For a real launch it is usually
better to start clean and not carry test customers and orders over.

### 7. Backups and safety

- **M0 has no automatic backups.** Until you move to M10, back up Atlas yourself every week and keep the folder
  somewhere safe (a cloud drive, not only this computer). No extra tools are needed:
  ```bash
  npm run db:backup                     # uses MONGODB_URI from .env, writes backups/<date-time>/
  ```
  A backup you have never restored is not a backup. Once a month, restore the newest one into a **new** database
  on the same cluster and check the counts it prints, then delete that copy in Atlas:
  ```bash
  npm run db:restore -- --from backups/<folder> --to-db nexthlon_restore_check
  ```
  The restore refuses to write into a database that already has data (add `--force` only when you really mean to
  replace one), so it can never overwrite the live store by mistake. The `backups/` folder is kept out of git.
- Turn on **Atlas alerts** (Project → Alerts) for connection and storage limits, and add your email.
- M0 clusters are **paused after a long period without use**. A live store will not hit that, but a test one might.

## Part 2 (no card needed): Cloudinary for the product photos

Cloudinary stores the photos and serves them from its own fast network. The free plan needs no payment card.

1. Sign up at <https://cloudinary.com/users/register_free>.
2. On the dashboard, open **Settings > API Keys** (or "Go to API Keys"). Note the **Cloud name**, the **API Key** and
   the **API Secret**.
3. In `.env` (on a host: its settings page) set:
   ```
   STORAGE_DRIVER=cloudinary
   CLOUDINARY_CLOUD_NAME=<cloud name>
   CLOUDINARY_API_KEY=<api key>
   CLOUDINARY_API_SECRET=<api secret>
   ```
4. Test it: `npm run setup:check`. It uploads and deletes a tiny test file.
5. Move the photos you already have: `npm run images:migrate`.

## Part 3: Before you deploy: checklist

- [ ] `npm run db:check` says **All good** with the Atlas string.
- [ ] `MONGODB_URI` has the database name (`.../nexthlon?...`) and no `<db_password>` left in it.
- [ ] Cloudinary works: a photo uploaded in the admin console opens from `res.cloudinary.com`.
- [ ] `npm run images:migrate` reports nothing left to move.
- [ ] On the host, set the same variables (`MONGODB_URI`, `STORAGE_DRIVER`, `CLOUDINARY_*`, `JWT_SECRET`, `SITE_URL`,
      `ADMIN_PATH`, `TRUST_PROXY`, ...) as **environment variables**, never in a file in the repository.
      The full list is in the README, under Deploying.
- [ ] Atlas **Network Access** allows the host.
- [ ] You know where the weekly `mongodump` backup goes (until you are on M10).

Anything you paste into a chat, an email or a screenshot (connection strings, API keys) should be treated as
leaked: change that password or key in Atlas / Cloudinary.

Nexthlon: everything pending before launch

A full list of what is left to finish the website and put it live. Written so that anyone, or an AI assistant, can work through it. Code is already built and committed in the project folder; what remains is mostly accounts, secrets, business details, content, and a few small website items.

How to use this document. Work top to bottom. Items marked [Owner] need a person with the account, card or legal details. Items marked [Developer] are code tasks in the project. Each setting name matches the file .env.example in the project folder. Never paste real passwords or keys into chat or email.

2. Secrets to generate [Owner]

Keep these in a password manager. Never share them in chat, email or a public repository.

  • JWT_SECRET: a long random string, at least 40 characters.
  • Push notification keys: run npm run push:keys once and keep the output (VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, VAPID_SUBJECT). Changing them later breaks saved devices.
  • MARKETPLACE_TOKEN: random, at least 24 characters.
  • SHIPROCKET_WEBHOOK_TOKEN: random, at least 16 characters.
  • Database user password: created in MongoDB Atlas.
  • Admin password and ADMIN_PATH: a private address for the admin console, for example /nx-console-7f3k.

3. Business details (shown on invoices and policy pages) [Owner]

  • Legal business name and registered address (STORE_LEGAL_NAME, STORE_ADDRESS).
  • GSTIN (STORE_GSTIN), GST state (STORE_STATE), and scheme (STORE_GST_SCHEME: regular or composition).
  • Support email, phone, and hours (STORE_SUPPORT_EMAIL, STORE_SUPPORT_PHONE).
  • Grievance officer name and contact (STORE_GRIEVANCE_OFFICER). Required by Indian e-commerce rules.
  • Trademark check for the name "Nexthlon" (it may be close to "Decathlon"). Get legal advice before launch.

The startup check warns in production while any placeholder value (text in square brackets) is still set.

4. Content to write or replace [Owner]

4.1 Policy pages

Terms and conditions, privacy policy, refund policy, shipping policy. They are templates with [square brackets]. Replace every bracket and have a lawyer or chartered accountant check them.

4.2 Products

  • Real photos (currently sample stock photos from Unsplash).
  • Descriptions, sizes and colours, and a SKU for every option.
  • HSN code, GST rate, country of origin, net quantity, and the manufacturer or importer name and address.
  • Packed weight in grams (used by the courier for pricing).
  • Remove or replace the sample products before launch.

4.3 Guides (content hub)

Sport guides and stories for /guides. Written by the team. Created through the admin API until an admin screen exists (see section 6).

4.4 Bundles ("Complete the kit")

Sets of 2 to 6 products with up to 30% off. Created through the admin API until an admin screen exists.

4.5 Offers and coupons

Decide the launch offers. Create coupons in the admin Coupons section. Decide whether the online-payment discount (admin Settings, 0 to 10%) is on.

4.6 Shipping and delivery rules

Confirm delivery times, the free-delivery threshold (currently ₹499) and the delivery fee (currently ₹40) match the courier.

5. Hosting steps, in order

  1. [Owner] Create the MongoDB Atlas cluster and database user. Copy the connection string and add the database name nexthlon before the ?.
  2. [Owner] Create the Cloudinary account and copy its cloud name, API key and API secret.
  3. [Owner] Create the hosting service, connect it to the code repository. Build command: npm install. Start command: npm start.
  4. [Owner] Enter every setting from .env.example on the host. Do not upload a .env file.
  5. [Owner] Point the domain at the host and turn on HTTPS. Set SITE_URL to the final https:// address.
  6. [Owner] Run the checks from the host shell: npm run setup:check and npm run db:check. Fix anything they report.
  7. [Owner] Create the first admin: npm run seed:admin. Sign in at the private admin address.
  8. [Owner] Add the real products and categories through the admin. Remove the sample products (npm run seed:products created them).
  9. [Owner] Test one real order end to end with a small amount: sign up, add to cart, pay, check the confirmation email, the WhatsApp message (if set), the invoice PDF and the tracking page.
  10. [Owner] Test each refund path once: cancel an item, return an item, refund to the wallet, refund to the original payment.
  11. [Owner] Test on a phone: sign up, checkout, push notifications, install the app to the home screen.
  12. [Owner] Set up backups: npm run db:backup on a schedule. Check a restore once on a copy with npm run db:restore.
  13. [Owner] Turn on monitoring: Sentry alerts, and check job status with npm run jobs:status.
  14. [Owner] Submit /sitemap.xml to Google Search Console.
  15. [Owner] Announce the launch only after steps 8 to 12 pass.

7. Things that only work after accounts are set up [Owner]

  • Payments (Razorpay) work only with live keys and approved KYC.
  • Shipping labels, PIN code checks and tracking updates need the Shiprocket account.
  • WhatsApp updates need Meta-approved templates named nx_order_placed, nx_order_shipped, nx_out_for_delivery, nx_order_delivered and nx_cod_otp.
  • COD codes need MSG91 with a DLT-approved OTP template (required in India).
  • Push notifications need the VAPID keys.
  • Emails need an SMTP or Brevo account; without one, production emails fail with a clear message.

8. Legal and business (outside the code) [Owner]

  • Check the admin dashboard and the job queue every day.
  • Watch refused-parcel (RTO) and COD refusal rates.
  • Answer product questions and review reviews weekly (admin Questions page).
  • Keep product photos and stock up to date.
  • Renew the domain, hosting, SSL, and move the database from M0 to M10 when orders grow.

# Nexthlon audit fixes — 17 November 2026

Follow-up authenticated admin results, including COD persistence and photo-editor checks, are in `docs/ADMIN-E2E-2026-11-17.md`. That report supersedes the earlier admin verification limits below for the features it actually exercised.

## Implemented

- Restored the missing `html` closing brace and sticky-header scroll padding in the shared CSS. No animation source, timing, 3D scene, visual effect, or design system was edited.
- Added durable payment completion, cancellation, return, and refund journals. The background worker resumes unfinished commerce work once per minute. Existing `JOBS_ENABLED=false` deployments must keep their standalone worker running for automatic recovery.
- Added atomic inventory receipts to stop repeated reservations/restocks, and atomic wallet receipts to stop duplicate credit after a lost response or failed history write. These are additive schema changes; receipts are hidden from ordinary model queries. Do not remove receipts while their operations can still be retried.
- Added optimistic concurrency to order saves. Stale customer/admin transitions receive a conflict instead of both changing stock or money.
- Refund intent is saved before money moves; refund recording is conditional and atomic. Manual refund forms retain a request identifier across retries.
- An uncertain original-payment refund no longer creates an automatic wallet fallback or a second gateway request. Recovery looks for the existing refund using a stable gateway note. An outcome the gateway cannot confirm remains pending and requires gateway/operator reconciliation; it is not reported as refunded.
- Payment callbacks resume unfinished stock, cart, invoice, and notification work. Database/transport failures are retried instead of being mistaken for sold-out products.
- Invoice and credit-note numbering can resume saved pending work using stable counter allocations. Financial operation receipts and counter allocations should be retained and their document sizes monitored as transaction volume grows; high-volume archival needs a separate tested retention strategy.
- Updated refund policy wording to describe wallet defaults, original-method choices, mixed payments, and pending gateway outcomes. Removed the draft About text and courier placeholders without inventing business details. Removed repeated standard product specification labels.
- Fixed optional test suites crashing when `TEST_MONGODB_URI` is absent and isolated the proxy subprocess fixture from the developer's `.env`.
